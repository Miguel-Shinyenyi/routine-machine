Today's topic: idempotency keys, explained through

A goal counts once, however many replays you watch. The broadcaster can show the same goal ten times; the scoreboard still moves by one. An idempotency key is that goal's match-clock stamp: when the same payment request arrives again, the server checks the stamp and keeps the first decision instead of scoring twice.

Saying the same promise twice does not make two promises. A request carrying the same key is the same act, repeated. The server's job is to recognise the repetition and answer with what it already decided, so the world changes once.

Landing the same trick on a replay does not add points. The judges score the run once. The idempotency key is the run number: send it again and you get the same score back, not a second one.

The analogy comes first, then the precise definition. You can always switch it off and read the plain version.
